# JourneyMap Ships(modid `jmships`)

Sable の船(Create Aeronautics の飛行船など)を、JourneyMap のミニマップと全体地図に「上から見たブロックの姿」で描く MOD。位置・回転・傾きに追従する。

- 対象: Minecraft 1.21.1 / NeoForge 21.1 / Sable 2.0.x / JourneyMap 6.x(窓口 v2)
- 入れる場所: 遊ぶ側(クライアント)だけ。ワールドを開く側には不要。
- Create Aeronautics 自体は必須ではない(Sable の船なら何でも映る)。

## この保管場所について

- **この MOD のプログラム・文書・試験は、ほぼすべて生成 AI が書いた**(Anthropic の Claude を、Claude Code で動かした)。作者は、何を作るかを決め、出来上がった物をゲームの中で確かめた。
- ライセンスは MIT(本文と、参考にした 2 つの MOD の表示は [LICENSE](LICENSE)。jar の中では `LICENSE_jmships.txt`)。
- JourneyMap には、公式の窓口(journeymap-api)だけを使っている。窓口の jar は、この MOD の jar に入れていない。
- **非公式の追加 MOD。** JourneyMap・Sable・Create Aeronautics の作者に、この MOD のことを問い合わせないでほしい。
- コンパイルに使うほかの MOD の jar は、この保管場所に入っていない(下の「作り方・試し方」)。組み立てた jar は Releases に置いてある。

## 仕組み

1. `map/ShipScanner` が、クライアントが持っている船のブロックを読み、地図色(バニラの地図と同じ色)の立体の表にする。2 秒ごとに読み直す(大きさが変わったときはすぐと、その 0.25 秒後にもう一度。Sable は、届いたチャンクだけを並べるので、大きさが先に届くと、新しいブロックの入ったチャンクを読み落とすことがある)。
2. `map/Projector` が、船のいまの姿勢で真上から見下ろした絵を作る。絵の 1 画素は世界の 1 マス(JourneyMap の地図と同じ細かさで、同じ升目)。ブロックを「回った箱」として、マスの中心を通る縦の線との当たりを見るので、斜めの船も正しいマスに出る。高さも記録し、段差にはバニラの地図と同じ明暗をつける。
3. `map/Visibility` が、1 画素ごとに「同じ形のブロックがそこにあったら地図に描かれるか」を決める。地上の地図用と洞窟の地図用の 2 通り(決まりの中身は裁定の文書)。
4. `jm/ShipTexture` が絵を自前のテクスチャに描く。船 1 隻につき、地上の地図用と洞窟の地図用の 2 枚。
5. `jm/ShipOverlays` が JourneyMap の公式の窓口(画像の貼り付け)でテクスチャを地図に貼る。2 枚は「どの種類の地図に出すか」を分けて登録するので、選ぶのは JourneyMap。洞窟用は、洞窟の地図が画面に出ている間だけ描いて貼る(一度作ったテクスチャは、船を手放すまで持っておく)。JourneyMap は貼る位置をブロック単位でしか指定できないので、貼る枠は動かさず、枠の中で絵のほうを動かす。船が枠の端に近づいたら枠を移す。止まっている船の絵も 2 秒ごとに JourneyMap へ渡し直す(JourneyMap が絵を手放したり受け取らなかったりしても、船が動くまで消えたままにならないように)。

JourneyMap 本体には手を入れていない(mixin なし)。JourneyMap の更新で壊れにくい。

## 分かっている制限

- 映るのは、自分のクライアントに読み込まれている船だけ。遠くの船は映らない(離れると消える)。
    - どこまでの船がクライアントに届くかは、サーバーの Sable が決める。Sable の設定 `sub_level_tracking_range`(サーバーの `config/sable-common.toml`。既定は 320 ブロック)より自分から遠い船は、サーバーが送ってこないので、この MOD には見えない(Sable 2.0.3 の中身で確認)。
    - この距離は高さも含めた直線の距離。高く飛んでいる船は、横の距離がもっと近くても消える。境目のあたりを飛ぶ船は、出たり消えたりする。
    - 地図の描画距離・クライアントの描画距離とは関係がない。全体地図は 320 ブロックより遠くの地形も映すので、そこを飛ぶ船は地形の上に映らない。地図を仲間と共有する MOD を入れている場合も同じで、共有された遠くの地形の上の船は描けない。描くには、遠くの船の位置と形を送るサーバー側の仕組みが要る(この MOD はクライアントだけで動くので持っていない)。
- 洞窟の地図では、層より上を飛ぶ船は描かない(裁定の決まりのとおり。同じ場所のブロックも JourneyMap は描かない)。JourneyMap は、自分が屋根の下(家の中など)にいるとミニマップを自動で洞窟の地図に切り替えるので、そのあいだは空を飛ぶ仲間の船がミニマップから消える。
- 1 隻の船を描く途中で思わぬ誤りが起きたときは、その船だけを地図から外し、2 秒ごとに描き直しを試す(記録に一度だけ書く)。ほかの船は描き続ける。
- 色はバニラの地図の色。JourneyMap の地形の色とは少し違う。ガラスなど地図色のないブロックは透ける。
- Create の「動く仕掛け」(プロペラなど、ブロックでなくなっている部分)は描かない。
- 名前は全体地図でマウスを重ねたときだけ出る。
- 船のまわりの世界が変わったとき(上に屋根を作ったなど)は、最長 2 秒遅れて絵に反映される。
- 洞窟の地図で JourneyMap と合わせきれていない点は、裁定の文書の末尾にまとめた。
- 試験で通っていない経路: 船の大きさが変わって絵を作り直すところ(0.25 秒後の読み直しを含む)、止まっている船の絵を渡し直すところ、1 隻だけ描けなくなったときに外して試し直すところ、ミニマップが自動で洞窟の地図に切り替わったとき(全体地図で洞窟の地図を選んだ場合は確認済みで、同じ仕組みを通る)。
- 船のチャンクがまだ届いていないときに前の絵を保つ仕掛けは、Sable 2.0.3 の中身では働かない(Sable は届いていないチャンクを並べないので、読んだ絵は前の絵に置き換わる)。Sable は船とそのチャンクをまとめて送るので、困るのは船が大きくなったときだけで、上の読み直しで補う。
- 動いている船は毎ティック描き直す。絵を作る計算は、長さ 40 ブロック級の船で約 0.4 ミリ秒、150 ブロック級で約 2 ミリ秒(机上の計測。描くかどうかの判定の分は含まない)。本番の大きな船での体感は未確認。

## 作り方・試し方

```
python tools/run_gradle.py run-logs/build.log build          # jar は build/libs/jmships-0.2.1.jar
python tools/run_gradle.py run-logs/visual.log runVisual     # 試験用のクライアントが 1 分ほど開いて自動で閉じる
```

- `runVisual` は、平らな世界を新しく作り、船を 3 隻組み立てて(1 隻目は石の屋根の下に半分入れる)、画面写真を `run-visual/screenshots/jmships-0*.png` に 5 枚残す。合否は写真を目で見て決める(結果ファイルは「撮れた」ことしか言わない)。
- 単体試験(`build` に含まれる)は、絵を作る計算と、描くかどうかの決まりを確かめる(15 件)。
- コンパイルに要る jar は、この保管場所には入れていない。
    - Sable: `../ColonyPatchServer/test-jars/sable-neoforge-1.21.1-2.0.5.jar`(隣のプロジェクトと共用)
    - JourneyMap の窓口: `libs/journeymap-api-neoforge-2.0.0-1.21.1.jar`(JourneyMap の jar の中の `META-INF/jarjar/` にある)
    - JourneyMap 本体(試験用のクライアントだけが使う): `test-jars/journeymap-neoforge-1.21.1-6.0.7.jar`
